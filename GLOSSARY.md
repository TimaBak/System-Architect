# Глоссарий системного архитектора

| Термин | Рабочее значение |
|---|---|
| Architecture Decision Record (ADR) | Короткая запись значимого решения, его контекста, альтернатив и последствий |
| Architectural fitness function | Повторяемая проверка нужного свойства или ограничения архитектуры |
| Architectural quantum | Часть системы с определёнными границами связанности и характеристиками независимости в развёртывании |
| Availability | Доля времени или запросов, когда критическая функция доступна по определённому SLI |
| Blast radius | Область, на которую распространяются последствия отказа или изменения |
| Bounded context | Граница модели и языка конкретной предметной области |
| Choreography | Процесс, возникающий из реакции самостоятельных участников на события |
| Cohesion | Насколько элементы компонента объединены общей ответственностью |
| Connascence | Вид зависимости, из-за которого элементы обязаны согласованно изменяться |
| Consistency | Правила наблюдения и согласования состояния в конкретной модели данных |
| Contract | Обещанное внешним потребителям поведение API, схемы события или протокола |
| Coupling | Сила и форма зависимостей между компонентами |
| CQRS | Разделение ответственности за чтение и изменение модели/потока обработки |
| Domain event | Событие о значимом завершившемся факте предметной области |
| Eventual consistency | Сходимость копий или проекций состояния при выполнении заданных условий |
| Idempotency | Повтор операции не меняет результат сверх эффекта первого корректного применения |
| Invariant | Условие, которое должно сохраняться при допустимых переходах состояния |
| Latency | Время от запроса до наблюдаемого результата в конкретной точке измерения |
| Logical component | Часть с предметной ответственностью; не обязательно отдельный процесс |
| Modularity | Разделение системы на части с контролируемыми зависимостями |
| Observability | Возможность судить о внутреннем поведении системы по её внешним сигналам |
| Orchestration | Координатор определяет последовательность и реакции участников процесса |
| Outbox | Атомарная фиксация бизнес-изменения и намерения опубликовать сообщение в одной транзакционной области |
| RPO | Допустимая потеря восстановленных данных, выраженная временем или другой единицей |
| RTO | Целевое время восстановления функции после нарушения |
| Saga | Координация распределённого бизнес-процесса через локальные транзакции и компенсирующие действия |
| SLI / SLO | Измеримый показатель услуги / его целевое значение |
| Temporal coupling | Зависимость участников от одновременной доступности и своевременного ответа |
| Trade-off | Компромисс: улучшение одной характеристики за счёт другой |
| Transaction boundary | Область, внутри которой выполняются заявленные гарантии атомарности |
| Zero-downtime deployment | Выпуск версии без недопустимого перерыва в обслуживании определённых сценариев |

## О терминах

Точный смысл всегда зависит от сценария. Например, «надёжность» платежей, API и архива данных измеряется совершенно разными критериями. Не используйте англоязычный термин как замену требованию.
