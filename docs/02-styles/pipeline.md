# Конвейерная архитектура (Pipeline / Pipes and Filters)

**Источник:** глава 12, стр. 205–217.

## Идея

Данные проходят через цепочку специализированных **фильтров**, соединённых **каналами**. Каждый фильтр делает одну ограниченную работу: получает, проверяет, преобразует, обогащает или выводит результат.

~~~text
Input → Parse → Validate → Normalize → Enrich → Output
         |         |                     |
      failure    reject                retry
~~~

В книге рассматриваются роли producer, tester, transformer, consumer. Конвейер может выполняться внутри одного приложения или быть распределённым. Разделение по процессам — отдельное решение.

## Что определить до выбора технологии

- Формат и версионирование передаваемых данных.
- Тип канала: поток, локальная очередь, файл, брокер.
- Условия завершения и поведение при частичной обработке.
- Порядок, повторные доставки и необходимость идемпотентности.
- Допускается ли параллелизм и как сохраняется порядок.
- Где создаётся журнал ошибок и как возобновляется обработка.

## Кейc: обработка документа

При загрузке документа система выполняет: антивирусную проверку → извлечение метаданных → нормализацию → классификацию → индексирование. Отказ классификатора не обязательно должен отменять сохранение оригинала. Определите политики per-stage: пропустить, остановить, повторить, отправить в ручной разбор.

## Плюсы

- Разделение труда между этапами и переиспользуемые простые фильтры.
- Довольно естественная поддержка потоковой обработки.
- Возможность локально тестировать преобразование на входных и выходных данных.
- Удобство адаптации последовательности при независимых фильтрах.

## Минусы

- Зависимость от общей схемы данных и порядка этапов.
- Сложность возврата назад и согласования побочных эффектов.
- При распределении — задержки, сеть, повторная доставка и трассировка.
- Фильтры со скрытым состоянием делают воспроизведение результата труднее.
- Не каждый интерактивный бизнес-процесс естественен как цепочка преобразований.

## Контрольный список

1. Можно ли запускать этап повторно без искажения результата?
2. Кто владеет промежуточными объектами и временем их хранения?
3. Что происходит с плохой записью среди миллиона хороших?
4. Нужна ли backpressure при перегрузке потребителя?
5. Где хранятся checkpoint, прогресс и информация о версии алгоритма?
6. Что произойдёт, если два экземпляра фильтра обрабатывают одно событие?
