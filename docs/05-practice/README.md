# V. Практическая работа Software / Solution Architect

Сильный архитектор не только рисует систему. Он выбирает архитектурно значимые качества, создаёт рамки решений, помогает команде реализовать изменения и проверяет результаты в эксплуатации.

## Четыре направления ответственности

| Направление | Результат |
|---|---|
| Бизнес ↔ архитектура | Решения связаны с измеримыми целями и ограничениями |
| Архитектура ↔ код | Компоненты, контракты и запреты зависимостей соблюдаются |
| Архитектура ↔ инфраструктура | Свойства качества поддерживаются реальным развертыванием |
| Архитектура ↔ команды | Ответственность за изменения и инциденты не размыта |

## Что сдаёт архитектор

**Достаточный, не чрезмерный** набор материалов:

1. Описание контекста и критических пользовательских сценариев.
2. Перечень качеств с критериями и владельцами.
3. Карта логических компонентов, внешних интеграций и потоков данных.
4. Выбранные границы развертывания и владения состоянием.
5. ADR на критичные структурные решения.
6. Реестр рисков и план наиболее важных экспериментов.
7. План безопасной доставки, наблюдаемости и восстановления.
8. Правила пересмотра архитектуры.

**Источник:** третья часть книги, главы 21–27, а также облачные и командные разделы глав 10–18. Инструментальные способы проверки и runbook-детали дополнены здесь практическими рекомендациями.
