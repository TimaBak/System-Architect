# VI. Сквозные учебные кейсы

Это **модели проектирования**, а не описания конкретных production-систем и не готовые спецификации. Цель — показать связь требований, границ, архитектурных стилей, данных, отказов и инженерных решений.

1. [SaaS-платформа с подписками и платежами](saas-platform.md) — как начать с разумной конструкции и подготовить эволюцию.
2. [Платформа управления подписками и VPN-доступом](vpn-subscription-platform.md) — как развести управление, выдачу доступа, устройства, телеметрию и внешние интеграции.
3. [Архитектурное ката](architecture-kata.md) — упражнения на сравнение решений.

## Что фиксировать в каждом кейсе

- бизнес-цель и допущения;
- критические свойства и их критерии;
- доменные границы и владельцы данных;
- выбранный стиль и отвергнутые альтернативы;
- данные, взаимодействия, режимы отказов;
- безопасность и эксплуатация;
- ADR, эксперименты и триггеры пересмотра.

При обсуждении реальных проектов сначала замените демонстрационные допущения измеренными фактами. Решения из кейса нельзя переносить без анализа условий.
